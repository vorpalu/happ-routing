# Happ / Xray: компактные геобазы

Шаблон Remnawave для Happ с небольшой собственной базой `geosite.dat` и базой российских IP `geoip.dat`. Подготовлен для снижения расхода памяти при запуске туннеля на iOS. Это отдельный комплект: его JSON и геобазы нужно применять вместе.

## Маршруты

| Категория | Маршрут |
| --- | --- |
| `geosite:ru` | Напрямую: MetaCubeX `category-ru` и сохранённые российские домены из предыдущего шаблона, включая `.ru`, `.su`, `.рф` |
| `geoip:ru` | Российские IPv4/IPv6 напрямую, если доменное правило не выбрало маршрут |
| `geosite:apple` | Apple напрямую |
| `geosite:games` | Steam, игровые платформы, игровые домены и загрузочные CDN напрямую |
| `geosite:games-proxy` | Ubisoft/Uplay и Blizzard/Battle.net через VPN, с приоритетом перед общими игровыми правилами |
| `geosite:trackers` | Публичные торрент-трекеры напрямую |
| `geosite:ads` | Рекламные домены блокируются |

Распознанный протокол BitTorrent направляется напрямую. Это не гарантия распознавания всех зашифрованных соединений, DHT и пиров. Не все игровые серверы можно определить по доменам. Доменная блокировка также не удаляет всю рекламу YouTube, которая может приходить с адресов самого видео.

Покрытие российских ресурсов определяется списками и GeoIP, а не гарантией принадлежности каждого сайта российскому сервису. Рекламное правило имеет приоритет над российскими доменами.

## Размер и проверка

Первоначальная сборка: JSON — 3 357 байт; GeoSite — 110 192 байта; GeoIP — 397 536 байт. Актуальные размеры, число записей и контрольные суммы находятся в `manifest.json`.

Шаблон с подставленным тестовым `proxy` прошёл `xray run -test` на Xray 26.3.27 для macOS ARM64. Проверены все 1 009 российских правил из предыдущего JSON, соответствие геокатегорий профилю Happ, маршруты Ozon, Кинопоиска, 2ГИС, Apple, Steam, Ubisoft/Blizzard, рекламы и YouTube.

В одном сравнительном запуске проверки на компьютере максимальный RSS составил примерно 122 МиБ для старого JSON с ранее скачанной полной базой, 44 МиБ для старого JSON со свежей полной MetaCubeX и 41 МиБ для этого комплекта. Это измерение проверки конфигурации на компьютере, без реального VPN-транспорта и туннеля iOS. Оно не доказывает, что Happ на iPhone всегда уложится в 50 МБ. Фактическую работу на iPhone нужно проверить отдельно.

## Подключение в Remnawave

1. Убедитесь, что `geosite.dat` и `geoip.dat` опубликованы в публичном репозитории и доступны по адресам из `happ-routing.json`. GitHub Pages не требуется.
2. В шаблон **Xray JSON** вставьте содержимое `xray-json.json`. Remnawave должен добавить выбранный сервер с тегом `proxy` первым в `outbounds`, как в стандартном генераторе. Сам шаблон не содержит VPN-серверов и не предназначен для запуска вне панели.
3. В выдаваемую Happ подписку добавьте HTTP-заголовок **`routing`**. Его значение — одна полная строка из `routing-header.txt`, начинающаяся с `happ://routing/onadd/`. Это значение, а не отдельный JSON-шаблон и не правило выбора типа ответа.
4. Если панель позволяет задавать такой заголовок только для ответа Happ, используйте эту настройку. Уже настроенный тип ответа **XRAY_JSON** сохраните. Не заменяйте общий раздел Response Rules содержимым `happ-routing.json`.
5. Обновите подписку в Happ. Убедитесь, что профиль **RU DIRECT Lite** загрузил обе новые геобазы, затем переподключите VPN. При ошибке загрузки Happ может сохранить прежний профиль, поэтому одно обновление списка серверов не подтверждает смену геобаз.

В `happ-routing.json` перечислены **все** геокатегории из Xray JSON и включено `UseChunkFiles`. Это необходимо для согласованности профиля при оптимизации геобаз. `LastUpdated` записан как UNIX-время. Ссылки на `.mrs` или `.srs` вместо `.dat` не подходят.

По официальной документации Happ, JSON передаётся ядру без переписывания правил интерфейсом. Геобазы и DNS туннеля задаёт сопровождающий профиль. Поэтому для этого комплекта недостаточно заменить только список доменов в интерфейсе приложения.

Файл `routing-header.txt` не скачивается клиентом по своей GitHub-ссылке: содержимое заголовка отдаёт именно Remnawave. Новые версии самих геобаз доступны по постоянным URL. Happ ограничивает частоту их обновления; если требуется форсировать обновление, обновите в панели значение заголовка свежей строкой из `routing-header.txt` с новым `LastUpdated`.

## Обновление списков

В репозитории есть GitHub Actions: ежедневная сборка и ручной запуск **Actions → Update routing databases → Run workflow**. После публикации убедитесь, что Actions разрешены и первый запуск завершился успешно. Защита основной ветки может требовать отдельной настройки записи для workflow. В неактивных публичных репозиториях GitHub может остановить запуск по расписанию.

Сборка скачивает свежие MetaCubeX GeoSite/GeoIP, оставляет нужные категории, объединяет российский список с `source/extra-domains.json`, убирает дубли и проверяет размер. `source/extra-domains.json` — сохранённый снимок дополнительных доменов, он сам по себе не обновляется из исходного российского репозитория. Расширение `category-ru` обновляется из MetaCubeX.

Ручная сборка (Python 3.10+, без сторонних пакетов):

```sh
python3 scripts/build.py --base-url https://raw.githubusercontent.com/vorpalu/happ-routing/main
```

При смене аккаунта, репозитория или ветки задайте соответствующий `--base-url` и заново возьмите `routing-header.txt`. После изменения категорий также проверьте Xray JSON и профиль Happ вместе.

## Источники

- [MetaCubeX/meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat): GeoSite и GeoIP, лицензия GPL-3.0. Ссылки и хеши использованных входных файлов записаны в `manifest.json`; текст лицензии включён в `LICENSE`.
- [Davoyan/mihomo-rule-sets](https://github.com/Davoyan/mihomo-rule-sets): источник расширенных российских доменов в предыдущем пользовательском шаблоне. Снимок этих правил сохранён в `source/extra-domains.json` вместе с явными исключениями пользователя.
- [Happ: JSON-конфигурации и оптимизация геобаз](https://github.com/HappDev/happ_su/blob/main/dev-docs/examples-of-links-and-parameters.md).
- [Happ: профиль подписки, заголовок routing и обновление геобаз](https://github.com/HappDev/happ_su/blob/main/dev-docs/routing.md).
- [Remnawave: поля профиля Happ, включая UseChunkFiles](https://github.com/remnawave/utils/blob/main/src/features/happ-routing-builder/model/types.ts).

В репозитории находятся только правила, открытые геоданные и шаблоны. Адреса VPN-серверов, пользовательские ключи и ссылки на подписки сюда не добавляются.
